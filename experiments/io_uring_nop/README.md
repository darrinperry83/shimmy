# NOP ring prototype, not guest syscall support

This experiment implements a bounded, process-local `io_uring` NOP engine using one immediately unlinked sparse host file. It exposes the Linux SQ, CQ, and SQE mmap offsets; publishes completions with acquire/release head and tail operations; and reports only NOP in its prototype probe. `tests/test_io_uring_nop.c` checks the three shared mappings, twelve NOPs across CQ wraparound, unsupported flags, and cleanup. The file is mode 0600 and unlinked before any result is returned; no host-wide ring or named persistent file is created.

The second prototype adds a registry of fd aliases backed by an internal anchor, a validated `iu_nop_mmap()` for only the three magic offsets, `iu_nop_poll_revents()` driven by CQ occupancy, and alias close cleanup. A sequential `fork()` test confirms each process can use its inherited alias and the child can close its copy without invalidating the parent's. The host test also checks ordinary duplicate descriptors have `FD_CLOEXEC` clear. These are hooks to integrate later, not evidence that arbitrary guest fd operations are intercepted today.

**Do not wire `io_uring_setup` to this yet.** A regular Darwin file descriptor is always poll-readable and accepts ordinary reads/writes, unlike an io_uring fd. Shimmy's real guest `mmap`, `poll`/`epoll`, `dup3`, `fcntl(F_DUPFD)`, `close_range`, `fork`, and `exec` paths do not call these hooks. The prototype does not handle `dup2` replacing an existing ring alias or simultaneous submitters after a fork; its mutex is process-local. `io_uring_enter` does not implement waiting when the CQ is empty, signal masks, linked SQEs, cancellation, or any operation except NOP. `io_uring_register` lacks the Linux probe wire structure and descriptor registration. The prototype's `-EAGAIN` for an unsatisfied `GETEVENTS` wait is a deliberate placeholder, not Linux wait semantics. None of this is a safe Linux-facing ring contract.

Next step: introduce a guest-private ring object with stable identity across duplicated fds and fork, enforce special mmap offsets and lengths, route poll/epoll/read/write/close correctly, then wire 425/426/427 as one unit. Add a disposable ARM64 guest test that exercises setup, SQ/CQ/SQE mmap, NOP enter and CQE, probe, wraparound, and fd lifecycle before changing `ENOSYS`. Compare parameters and errors to a Linux oracle. This experiment is a data-structure proof only.
