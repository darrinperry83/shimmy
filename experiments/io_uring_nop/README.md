# NOP ring prototype, not guest syscall support

This experiment implements a bounded, process-local `io_uring` NOP engine using one immediately unlinked sparse host file. It exposes the Linux SQ, CQ, and SQE mmap offsets; publishes completions with acquire/release head and tail operations; and reports only NOP in its prototype probe. `tests/test_io_uring_nop.c` checks three shared mappings, twelve NOPs across CQ wraparound, unsupported flags, and cleanup. The file is mode 0600 and unlinked before any result is returned; no host-wide ring or named persistent file is created.

**Do not wire `io_uring_setup` to this yet.** A regular Darwin file descriptor is always poll-readable and accepts ordinary reads/writes, unlike an io_uring fd. The prototype registry is keyed by one fd number: `dup`, `fcntl(F_DUPFD)`, `close_range`, `fork`, and `exec` do not preserve the right object lifetime. `io_uring_enter` does not implement waiting when the CQ is empty, signal masks, linked SQEs, cancellation, or any operation except NOP. `io_uring_register` lacks the Linux probe wire structure and descriptor registration. Shimmy's guest `mmap` currently accepts arbitrary file offsets and does not validate the ring's magic offsets/lengths. The prototype's `-EAGAIN` for an unsatisfied `GETEVENTS` wait is a deliberate placeholder, not Linux wait semantics. None of this is a safe Linux-facing ring contract.

Next step: introduce a guest-private ring object with stable identity across duplicated fds and fork, enforce special mmap offsets and lengths, route poll/epoll/read/write/close correctly, then wire 425/426/427 as one unit. Add a disposable ARM64 guest test that exercises setup, SQ/CQ/SQE mmap, NOP enter and CQE, probe, wraparound, and fd lifecycle before changing `ENOSYS`. Compare parameters and errors to a Linux oracle. This experiment is a data-structure proof only.
