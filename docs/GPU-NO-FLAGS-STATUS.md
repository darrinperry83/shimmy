# Default Metal desktop path

The GUI and CLI now both compile the guest GPU syscall `0x2002`. The host establishes the local Metal broker by default; the guest no longer needs a renderer selection flag. The GUI guest environment no longer injects `LIBGL_ALWAYS_INDIRECT=1`. The virtual DRM card supports the tested master/authentication exchange Aquamarine uses when it reopens the card.

In a disposable Arch root with no `RDMETAL_*`, `MESA_*`, `LIBGL_*`, or `GALLIUM_*` selector, both surfaceless and GBM `eglinfo` reported `rdmetal Metal (direct)`. A separate guest EGL triangle produced `RDMETAL_FIXTURE_DRAW result=0` in the host log, establishing an actual Metal draw. In isolated standalone Hyprland, EGL initialized, the broker capability query succeeded, and Hyprland entered its event loop. A metadata-only broker query returned the real IOSurface stride (14464 bytes) before first render.

The staged broker/KMS integration now issues an identity-only GBM carrier before a draw, keeps its IOSurface unavailable until the Metal fence completes, then presents the completed image in the same-process primary window. A 35-second isolated standalone Omarchy run without renderer selector variables logged `DRM_PRESENT_METAL` twice for the 3600×2338 built-in display and `[present-stats] path=drm_iosurface_metal ... cpu_framebuffer_bytes=0`. This proves a Metal-backed framebuffer reached the window; it does not prove the compositor's full GLES workload or sustained frames. Hyprland then aborted after Mesa reported `GL_OUT_OF_MEMORY` from `glTexImage(GL_RGBA/GL_RGBA8)` and an incomplete framebuffer. The rdmetal sample-resource allocator rejects textures larger than 256 pixels per edge while the screen routes RGBA8 sampler-bound resources up to 4096 pixels to it. That allocation path is under investigation. See `build/gpu-integrated-omarchy.log` for the measured run.

The completed broker/KMS unit tests cover stale/replayed FDs, pre-completion denial and buffer reuse. An authenticated Mach IOSurface transport has also passed a separate two-process test, but it is not yet wired to the full systemd desktop. Next gates are the texture/framebuffer allocation failure, sustained nonblack Metal frames, cross-process host-window presentation, ordinary-format fallback counts, secondary display, and login-to-desktop operation. The source branch should not be installed as the default driver until these pass.
