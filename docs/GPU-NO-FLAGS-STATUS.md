# Default Metal desktop path

The GUI and CLI now both compile the guest GPU syscall `0x2002`. The host establishes the local Metal broker by default; the guest no longer needs a renderer selection flag. The GUI guest environment no longer injects `LIBGL_ALWAYS_INDIRECT=1`. The virtual DRM card supports the tested master/authentication exchange Aquamarine uses when it reopens the card.

In a disposable Arch root with no `RDMETAL_*`, `MESA_*`, `LIBGL_*`, or `GALLIUM_*` selector, both surfaceless and GBM `eglinfo` reported `rdmetal Metal (direct)`. A separate guest EGL triangle produced `RDMETAL_FIXTURE_DRAW result=0` in the host log, establishing an actual Metal draw. In isolated standalone Hyprland, EGL initialized, the broker capability query succeeded, and Hyprland entered its event loop. A metadata-only broker query returned the real IOSurface stride (14464 bytes) before first render.

The staged broker/KMS integration now issues an identity-only GBM carrier before a draw, keeps its IOSurface unavailable until the Metal fence completes, then presents the completed image in the same-process primary window. An isolated standalone Omarchy run without renderer selector variables logged `DRM_PRESENT_METAL` twice for the 3600×2338 built-in display and `[present-stats] path=drm_iosurface_metal ... cpu_framebuffer_bytes=0`. This proves a Metal-backed framebuffer reached the window; it does not prove the compositor's full GLES workload or sustained frames.

The first GUI run then hit `GL_OUT_OF_MEMORY` because the Mesa sampled-resource allocator rejected large RGBA8 textures. The unified direct IOSurface resource and checked host image-upload operation cleared that allocation failure; Hyprland reported a complete monitor workbuffer (`status 36053`). The next run exposed a null `pipe_context->set_scissor_states` call; registering the callback advanced three shader variants. A later `glInvalidateFramebuffer` crash was traced to a process-global softpipe fallback pointer being destroyed by EGL's earlier probe screens. The fallback is now owned per Mesa screen. With that fixed, the latest isolated run reaches the same Metal framebuffer but stops in softpipe vertex translation: a non-direct depth/stencil framebuffer attempts to use rdmetal's custom vertex buffer as a softpipe buffer. That resource boundary remains open. Logs: `build/gpu-integrated-omarchy.log`, `build/gpu-upload-omarchy.log`, `build/gpu-scissor-omarchy.log`, `build/gpu-per-screen-omarchy.log`.

The completed broker/KMS unit tests cover stale/replayed FDs, pre-completion denial and buffer reuse. The image-upload test covers format conversion, sizes and lease/fence checks, and guest-memory copyin is range-checked. An audited Mach IOSurface transport passed a separate two-process test; the full systemd desktop wiring is still unverified. Next gates are the mixed-depth/vertex-buffer path, restrictive scissor, partial texture updates/readback, sustained nonblack Metal draws, cross-process host-window presentation, ordinary-format fallback counts, secondary display, and login-to-desktop operation. The source branch should not be installed as the default driver until these pass.
