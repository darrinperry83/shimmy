# `fanotify_init` (ARM64 syscall 262): event-backend blocker

Shimmy currently returns `EPERM` for both `fanotify_init` and `fanotify_mark` in `src/syscalls_ext.c`. No fanotify descriptor, mark registry, event queue, or permission-response path exists. This is an unsupported call, not a working implementation. The unconditional `EPERM` is not a faithful Linux errno for every caller: Linux permits a restricted notification-class group without `CAP_SYS_ADMIN`, while content and pre-content permission classes require that capability.

An init-only implementation that returns an inert pipe would claim a usable fanotify group while never producing marked filesystem events. Shimmy's current inotify pipe has that limitation already; fanotify clients can also depend on open/access permission decisions, event file descriptors or file handles, mount/filesystem mark scope, overflow records, and mark lifetime. A Darwin kqueue vnode watch on one path cannot supply those Linux contracts, particularly events caused through another path or process and synchronous permission gating. Forwarding a host-wide watcher would also cross Shimmy's guest-root boundary without a defined access policy.

Keep the runtime refusal until a guest-private notification service exists. Implement `fanotify_init` with `fanotify_mark` as one unit: validate flags and guest credentials, register marks against guest filesystem objects/mounts, generate Linux wire-format events with guest PID and usable guest file identities, make read/poll/epoll and descriptor inheritance coherent, and mediate permission responses before file access is committed. The first bounded version could explicitly reject permission classes and mount marks, but it must deliver real notification events for every admitted mark.

Test with a disposable ARM64 guest root: initialize a restricted notification group, mark a file and directory, create/modify/open them from another guest process, verify event masks, identities, and polling, remove the mark, close and duplicate the descriptor, and verify no events leak from host paths outside the guest root. Test denied flags and permission classes separately. The existing Linux UAPI is in `linux/fanotify.h`; the [Linux `fanotify_init(2)` manual](https://man7.org/linux/man-pages/man2/fanotify_init.2.html) and [fanotify(7)](https://man7.org/linux/man-pages/man7/fanotify.7.html) specify the class, event, mark, and descriptor contracts.
