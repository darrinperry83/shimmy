# ARM64 syscall table audit

This is a source audit, not a compatibility certificate. The machine-readable
[`audit-2026-11-18.json`](audit-2026-11-18.json) covers every numbered entry
in the installed Arch native `asm/unistd_64.h` header, records dispatch case
locations, and flags selected contracts needing manual review. Regenerate it
with `python3 docs/syscalls/audit_snapshot.py <Arch-root>/usr/include/asm-generic/unistd.h`.
The supplied generic header is used to record compat-only entries separately;
the adjacent native header supplies the actual AArch64 syscall list. The snapshot
retains both header hashes and the exact source commit. The source scan
did not execute guest code, exercise the desktop, or compare behavior against
a Linux kernel. Each row therefore says `compatibility: unverified`.

## Coverage and caveats

The native header has **327** numbered entries. **312** have at least one source
case label, **15** have none, and **5** numbers occur in more than one dispatcher.
The generic header also defines **20** time64 numbers in 403–423 (415 is a gap)
inside a compat-or-32-bit guard. Those are recorded in
`excluded_compat_entries` and are **not** missing native AArch64 work. The 15
without a case include Landlock 444–446, `memfd_secret`
447, `process_mrelease` 448, `cachestat` 451, `statmount`/`listmount` 457–458,
`mseal` 462, and newer 467–471. A missing case
reaches `linux_syscall_ext`'s `ENOSYS` default. The snapshot contains the
complete numbered list; header presence alone does not imply the local Arch
userspace calls that number.

Routing order matters. `shim.c` routes the network-owned set to `net.c`
before the main table. `syscalls.c` sends its default to the extended
table, whose default is `ENOSYS`. The duplicates are:

| Number | Calls | Effective route / audit consequence |
| --- | --- | --- |
| 59 | `pipe2` | `net.c` owns it; the extended implementation is unreachable through normal dispatch. |
| 137 | `rt_sigtimedwait` | Main handles it; extended unconditional `EAGAIN` is shadowed. |
| 153 | `times` | Main handles it; extended copy is shadowed. |
| 260 | `wait4` | Main handles it; extended copy is shadowed. |
| 441 | `epoll_pwait2` | `net.c` owns it; extended `ENOSYS` is shadowed. |

`clone` 220 and `clone3` 435 also have trap-handler paths; their table case
alone cannot describe their behavior. Sub-dispatch contracts matter for `ioctl`
29, `fcntl` 25, `prctl` 167, sockets 198–212, and filesystem/device paths.

## Source findings that block a broad compatibility claim

1. **Synthetic mount success:** `umount2` 39, `move_mount` 429, `fsconfig`
   431, and `mount_setattr` 442 return `0` without their Linux side effects
   (`src/syscalls_ext.c`). `mount` 40 has a narrow
   `/run/user` failure but otherwise returns success for a synthetic tree.
   `open_tree`/`fsmount` return a host `/tmp` directory fd; `fsopen`/`fspick`
   return an unconnected datagram socket. These are boot
   compatibility expedients, not a working Linux mount API. The separate
   experimental mount-family branch was withheld after a private boot failure.
2. **Guest PID versus Darwin PID:** bounded guest target handling now exists
   for `setpriority`/`getpriority` 140–141 and
   `setpgid`/`getpgid`/`getsid` 154–156. Their focused guest probes passed,
   but wider process-group, session, and priority behavior remains unverified.
3. **Shared host IPC namespace:** SysV message queues, semaphores, and shared
   memory 186–197 call Darwin's IPC APIs with guest keys/IDs
   (`src/syscalls_ext.c`). Some structures and command numbers are
   explicitly translated, which is substantive work. The key/ID namespace
   and ownership are still host-global; test collision, permission, cleanup,
   and cross-instance isolation before treating them as Linux-private IPC.
4. **Bounded values versus full side effects:** `setfsuid`/`setfsgid`
   151–152 still lack a separate guest filesystem-identity model.
   `adjtimex` 171 has a read-only subset and `getcpu` 168 reports a bounded
   virtual topology. The wider Linux behavior remains unverified.
5. **Signal masks in multiplexed waits:** `epoll_pwait` 22, `pselect6` 72,
   and `ppoll` 73 now reject non-null masks explicitly. Ordinary waits have
   focused guest probes, but the Linux atomic temporary-mask contract is not
   implemented.
6. **Capability model remains blocked:** the isolated `syscall/91-capset`
   branch has focused transition tests, but truthful ambient capability
   handling prevented a private Arch boot. PID 1 requested ambient raises
   for bits 0–62. A two-bit virtual model cannot satisfy that request without
   claiming unsupported privileges. That branch is not in this commit.

The 32 flags in the JSON are a prioritized **source-review queue**. They do
not imply all other entries are correct. Conversely, many unflagged calls
have tested bounded implementations; this scan does not grade those tests.

## Existing bounded evidence

`docs/syscalls/PROGRESS.md` and the per-call documents record ARM64 guest probes
for native AIO 0–4/292, POSIX timers 107–111, scheduler calls 118–123/125–127,
`preadv`/`pwritev` 69–70, `sendfile` 71, `waitid` 95, `process_vm_readv` 270,
`copy_file_range` 285, and others. Examples of checked-in probes include
`tests/guest-timer-gettime.c`, `guest-sched-setparam.c`, `guest-preadv.c`,
`guest-copy-file-range.c`, and `guest-waitid.c`. Their documented limits and
private boot smoke gates are useful evidence for *those subsets*. They do not
make the entire numbered row Linux-compatible, nor do private login tests
establish GUI or production stability.

## Next calls

1. Extend guest PID/process-group coverage beyond the bounded 140–141 and
   154–156 probes, and design guest-private SysV IPC (186–197). Use two
   isolated guest processes plus an unrelated host process in tests.
2. Replace mount-family false success with a coherent private mount-state
   model, or return truthful errors where systemd can fall back. Prove boot,
   mount visibility, fd behavior, and cleanup together; do not cherry-pick
   the withheld branch.
3. Treat capability 90–91/`prctl` 167 as a credentials subsystem, including
   full-mask ambient/bounding behavior, exec, `/proc`, and permissions. Keep
   the blocked two-bit branch isolated until its private boot gate passes.
4. Choose missing newer calls from observed app traces, then compare exact
   Linux error/side-effect behavior and run disposable ARM64 tests. Avoid
   implementing 15 absent native numbers solely to raise a coverage percentage.
