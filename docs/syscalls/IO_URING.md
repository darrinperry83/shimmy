# `io_uring_setup` (ARM64 syscall 425): blocked by ring-fd backend

Linux `io_uring_setup(entries, params)` returns a ring file descriptor and fills `io_uring_params` with the sizes and offsets needed to map submission (SQ), completion (CQ), and SQE memory through that fd. A program then writes SQEs and SQ tail in shared memory, calls `io_uring_enter` (426), reads CQEs and advances CQ head, and can use `io_uring_register` (427) for probes, buffers, files, eventfds, and other facilities. The ring fd also has `mmap`, `poll`, duplication, close, and process-lifetime semantics. Shared SQ/CQ head and tail publication must obey the acquire/release ordering described in Linux's implementation.

Shimmy currently returns `ENOSYS` for 425–427. Its `gmem_mmap` path maps a host fd or anonymous memory; it does not recognize a virtual io_uring fd and the special `IORING_OFF_*` offsets. The existing Linux AIO (`io_setup`/`io_submit`) prototype has a separate completion-ring address and synchronous regular-file requests; it is not an io_uring ring or descriptor. Returning a plausible fd from 425 without the ring mappings and 426/427 behavior would make applications believe they have a usable async I/O engine when they do not.

A bounded guest-private implementation can start with a ring registry and fd type, the exact ARM64 UAPI `io_uring_params`/SQ/CQ/SQE layouts, mmap offset routing, bounds-checked ring indices and memory ordering, and one supported operation such as `IORING_OP_NOP`. Implement 426 to consume SQEs and publish CQEs, 427 to report only genuinely supported operations, and handle poll/close/dup/fork/exec lifetime before enabling 425. Subsequent operations can reuse Shimmy's file I/O code only after descriptor ownership, cancellation, buffer pinning, ordering, and error completion are specified. Test the three syscalls **together** in a disposable ARM64 guest: setup, all three mappings, NOP submission/completion, CQ wraparound, invalid SQEs, unsupported feature probes, and fd lifecycle. Compare layouts and errors against Linux. Keep `ENOSYS` until that vertical slice passes; a setup-only success is not safe.

Primary sources: [Linux `io_uring/io_uring.c`](https://github.com/torvalds/linux/blob/master/io_uring/io_uring.c) and [Linux UAPI `include/uapi/linux/io_uring.h`](https://github.com/torvalds/linux/blob/master/include/uapi/linux/io_uring.h).
