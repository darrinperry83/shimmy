# `seccomp` (ARM64 syscall 277): blocked by syscall-entry policy enforcement

The `seccomp(operation, flags, args)` syscall installs strict or classic-BPF syscall filters and also exposes action and notification queries. Linux applies an installed filter on **every later syscall**, including calls made by child threads and inherited across fork/exec; actions can deny with an errno, kill, trap with `SIGSYS`, trace, log, or send a user notification. A successful install is a security promise, not an advisory hint.

Shimmy currently returns `ENOSYS` for syscall 277 in `src/syscalls_ext.c`. The `prctl` route reports `PR_GET_SECCOMP` as disabled and rejects `PR_SET_SECCOMP`. The guest signal model does not yet provide all `SIGSYS`/notification behavior. Returning success for `SECCOMP_SET_MODE_STRICT` or `SECCOMP_SET_MODE_FILTER` would let the guest believe it is sandboxed when it is not. The action/notification queries must not advertise facilities that cannot be enforced.

Keep syscall 277 at `ENOSYS` until Shimmy has complete per-thread/process filter state, classic-BPF verification and evaluation over `struct seccomp_data`, action precedence, thread synchronization, fork/exec inheritance, trap/signal and user-notification plumbing, and enforcement before every guest syscall path. Validate with disposable ARM64 guest programs that install a filter then attempt both allowed and blocked calls, including threads, fork/exec, signal actions, and the `prctl` route. The now-monotonic `PR_SET_NO_NEW_PRIVS` implementation needs a separate privilege-model review before it can support a security claim.

## Bounded evaluator foundation

`src/seccomp_bpf.c` now has an isolated, tested verifier and evaluator for a conservative classic-BPF subset over the Linux ARM64 `seccomp_data` layout. It accepts only 32-bit absolute loads, immediate loads, a few arithmetic/bitwise operations, forward jumps, and constant `ALLOW`/`ERRNO` returns. It rejects unknown instructions, out-of-range or unaligned loads, escaping jumps, unsupported actions, and programs without a final return. Invalid evaluation fails closed to `ERRNO(EPERM)`. The sanitizer test in `tests/test_seccomp_bpf.c` covers architecture, syscall number, argument inspection, and malformed programs.

`src/seccomp_runtime.c` now owns a private immutable copy of one verified filter and a monotonic `no_new_privs` snapshot field. `route_syscall()` checks the current guest thread's policy before net, core, and hypercall dispatch; the ordinary null-policy path is one branch. Thread clone, fork, and vfork copy the policy pointer. The host re-exec path carries a policy snapshot through a reserved, read-only pipe descriptor; guest-supplied `RDSECCOMP_*` variables are stripped, and a malformed snapshot fails closed before guest execution. The sanitizer test covers policy copying, allow/deny, fork, re-exec, and malformed transfer. An ARM64 guest test confirms `PR_SET_NO_NEW_PRIVS` is monotonic and survives a new guest thread, fork, and guest exec, including a guest attempt to spoof the inheritance variable. A fresh private Arch boot after the `no_new_privs` change reached login with D-Bus broker and launcher settled.

This is a **dependency slice, not an enabled seccomp implementation**. No guest syscall can install a policy, so the predispatch branch does not yet prove guest filter enforcement. The current subset lacks stacked-filter precedence, full classic BPF, kill/trap/trace/log/user-notification actions, and guest instruction pointer. It also has not established that guest code cannot modify Shimmy's own in-process memory or bypass a rewritten syscall site; that must be resolved before claiming security isolation. #277 remains `ENOSYS`, and `PR_SET_SECCOMP` remains rejected until guest install/deny/allow/clone/fork/re-exec tests and the private boot gate all pass.
