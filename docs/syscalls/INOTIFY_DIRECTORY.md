# Inotify directory names and explicit-close lifecycle

This increment extends the bounded kqueue backend from `INOTIFY_INIT1.md`. A directory watch requesting `IN_CREATE` or `IN_DELETE` now snapshots up to 512 immediate child names and compares them after a Darwin vnode write notification. It emits Linux-format events containing a NUL-terminated, 16-byte-padded child name and `IN_ISDIR` for directory children. It does not traverse child directories. Watched-file events continue to use their existing path.

Guest `dup`, `fcntl(F_DUPFD*)`, and `dup3` aliases are tracked. Explicit `close` of an alias closes that descriptor, and closing the final alias wakes and joins the instance worker, then releases its watches, kqueue, writer, and reserved descriptors. Clobbering an inotify alias with `dup3` is refused with `EOPNOTSUPP` rather than silently losing the old instance. A forked child still has no inherited worker; `inotify_add_watch` on its inherited instance returns `EOPNOTSUPP`. The fork mutex handlers prevent a copied locked state from deadlocking the child.

This remains a **subset**, not full Linux inotify. Kqueue coalesces directory writes, so a child created and deleted between scans can be missed. Rename/move pairing and cookies, queue-overflow guarantees, close-range teardown, inherited-watch operation after fork, clobbering an inotify alias with `dup3`, and unlimited directory sizes are not implemented. A scan failure reports `IN_Q_OVERFLOW` and leaves the previous snapshot intact. Directory snapshots are limited to 512 entries, and each inotify instance is limited to 128 watches. Production use needs a resource and semantics review.

Tests: `./build.sh cli`, `sh tests/run-inotify-directory-events.sh`, and `sh tests/run-inotify-directory-guest.sh`. The ARM64 guest test covers file and directory child create/delete names, `IN_ISDIR`, `poll`/`read`, fork refusal, aliasing through `dup`, `fcntl` and `dup3`, and final close. Existing watched-file and removal regressions remain in `tests/run-inotify-file-events.sh`, `tests/run-inotify-file-guest.sh`, and `tests/run-inotify-rm-watch.sh`. All passed. A fresh private APFS-cloned Arch boot also reached a login prompt with the D-Bus broker and launcher settled; that is a systemd smoke gate, not proof of every inotify behavior.
