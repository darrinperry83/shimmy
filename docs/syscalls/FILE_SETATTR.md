# `file_setattr` (ARM64 syscall 469): blocked by guest file-attribute state

Linux's five-argument ABI is `file_setattr(dfd, filename, struct file_attr *attr, size, at_flags)`. The version-zero structure is 24 bytes and carries extended inode flags, extent hints, and project ID. Linux accepts only `AT_SYMLINK_NOFOLLOW` and `AT_EMPTY_PATH`, checks the versioned structure, resolves a path or descriptor, then calls the filesystem's attribute setter. The setter reads old attributes, checks inode ownership, Linux capabilities and flag combinations, updates persistent inode state, and notifies watchers.

Shimmy currently translates guest file operations to Darwin descriptors and paths. It does not have a coherent Linux `file_attr` store shared by `file_getattr`, write/open/truncate/rename/unlink, statx, and file creation. Darwin `chflags` cannot supply Linux project IDs, extent settings, DAX, or all filesystem-specific flags. Applying a host immutable or append flag to the user's APFS-backed root could also prevent host-side recovery while failing to match Linux capability and namespace checks. Returning success for zeroed attributes would be unsafe: on Linux that request can **clear** existing flags.

Keep syscall 469 on its current `ENOSYS` fallback. A later implementation needs a per-inode, guest-owned attribute model with lifetime and rename/hard-link identity; coherent enforcement in every mutating file path; validated descriptor provenance; and Linux permission/capability rules. Then test versioned-argument errors, flags, path and fd forms, immutable/append behavior, project ID and extent settings, cross-call readback, and restart persistence against a Linux ARM64 oracle. A path-only host `chflags` wrapper is insufficient.

Primary source: [Linux `fs/file_attr.c` syscall and setter](https://github.com/torvalds/linux/blob/master/fs/file_attr.c); ABI: [Linux `include/uapi/linux/fs.h`](https://github.com/torvalds/linux/blob/master/include/uapi/linux/fs.h).
