# `io_submit` (ARM64 syscall 2): bounded regular-file subset

This branch extends the isolated native-AIO prototype with a bounded `io_submit(ctx, nr, iocbpp)` route. A live context can accept `IOCB_CMD_PREAD` and `IOCB_CMD_PWRITE` for ordinary files whose pinned descriptor resolves beneath the guest root. The request uses an explicit offset, no RWF or eventfd flags, and at most 1 MiB of data. Submission copies the Linux ARM64 64-byte `iocb` from guest memory, performs the operation synchronously, and queues a genuine 32-byte `io_event` containing the user data, iocb address, result or negative errno, and zero secondary result. It mirrors the completion to the guest ring and updates its tail. The context lock serializes submission with `io_destroy`; the latter can release a context after this synchronous work finishes.

This is a deliberately limited AIO subset, not arbitrary asynchronous dispatch. It excludes sockets, synthetic and host-private descriptors, vectored I/O, fsync, poll, eventfd notification, nonzero RWF flags, and reads or writes larger than 1 MiB. The completed family reconciles sequential direct-ring consumption with the host completion queue; concurrent ring readers and syscall consumers remain unverified. `io_getevents` and no-mask `io_pgetevents` now retrieve these completions.

Focused proof: `./build.sh cli` and `python3 tests/run-io-submit.py --sysroot <installed Arch root>` pass. The test uses a disposable guest root, checks real regular-file write/read and ring events, and checks invalid arguments. All six AIO family tests pass together. Queue-full and wraparound, concurrent submit/getevents/destroy, invalidated guest buffers, partial batches, and fork/exec handling need further validation before broad compatibility claims.

Primary sources: [Linux `fs/aio.c` submission and completion](https://github.com/torvalds/linux/blob/master/fs/aio.c) and [Linux `aio_abi.h` structures](https://github.com/torvalds/linux/blob/master/include/uapi/linux/aio_abi.h).
