# `mq_open` (ARM64 syscall 180): blocked by POSIX message-queue backend

Linux `mq_open(name, oflag, mode, attr)` opens or creates a named queue and returns a descriptor. That descriptor is useful to `mq_timedsend`, `mq_timedreceive`, `mq_getsetattr`, `mq_notify`, `poll`, `close`, `dup`, and inheritance across `fork`/`exec`; queue names persist until `mq_unlink`. Creation also applies mode, message-size/count limits, and per-user queue accounting. The queue orders messages by priority and supports blocking and absolute-timeout operations.

Shimmy currently sends ARM64 syscalls 180–185 to `ENOSYS`. Its Darwin-host SysV message-queue forwarding at 186–191 is a different API: a SysV queue ID cannot serve as a POSIX queue descriptor or reproduce POSIX naming, readiness, notification, and lifecycle. Darwin provides no POSIX mqueue syscall backend in this implementation. Returning a synthetic descriptor from `mq_open` while send, receive, notify, and attribute calls still fail would falsely indicate a usable queue.

This branch adds a **process-local model only** in `src/mqueue_core.c`: guest-private names, create/exclusive/open, priority-ordered nonblocking messages, bounded capacity and size, readiness-state queries, and unlink with open-handle survival. `tests/run-mqueue-core.sh` exercises these against the compiled core. It has no host-global names or files. It is linked into the CLI but **not wired to syscall 180**, so no guest receives a false success. A process-local mutex and pointers cannot by themselves preserve one queue across guest shim processes or an exec, and the model does not yet implement blocking timeouts, mode/credentials, notification, or resource accounting.

Keep the current `ENOSYS` result. Next add an fd adapter and a queue registry shared by all guest shim processes for one installation/session, with shared open-file state, mode/credentials, limits/accounting, blocking and timeout behavior, poll readiness, notification ownership, and `dup`/`fork`/`exec`/`close` lifecycle. Then test `mq_open` together with send, receive, attributes, notify, unlink, `poll`, `dup`, `fork`, `exec`, and `close` in a disposable ARM64 guest root. Compare error and race cases against Linux before enabling syscall 180.

Primary source: [Linux `ipc/mqueue.c`](https://github.com/torvalds/linux/blob/master/ipc/mqueue.c), especially the `mq_open` syscall and mqueue file operations.
